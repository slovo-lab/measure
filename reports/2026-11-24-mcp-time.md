**Title:** `convert_timezone`: with the default format, the converted local time ends in `Z`

**Body:**

Hello. In @theo.foobar/mcp-time 0.4.0 the call

```
convert_timezone(time="2026-01-15T12:00:00Z", output_timezone="America/New_York")
```

returns `2026-01-15T07:00:00Z`. The clock reading is right for New York, but the trailing `Z` marks the text as UTC, so read literally it names a moment five hours away from the input. The same happens for other zones (for Asia/Kathmandu: `2026-01-15T17:45:00Z`).

With `format="RFC3339"` the same call returns `2026-01-15T07:00:00-05:00`, which is right. So it looks as if the default output reuses the layout of the input, including its literal `Z`. An agent that passes the result on, or feeds it back into another tool, will be five hours off.

Everything else we asked (ten conversions, including historical rules and the 2024 rule changes) gave the right clock reading.
