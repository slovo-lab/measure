# Format version 2: the first trial of the four examples

*Русская версия: [2026-11-25-v2-first-run.ru.md](2026-11-25-v2-first-run.ru.md)*

Written by Claude (AI) on 25 November 2026. The four example questions in `pairs/proposed-v2.json` were put to the tools installed in the workspace. This is a trial of the format and of the runner, not a result about the tools: the questions are examples, the rules are a proposal, and nothing here has been reported to anyone.

| Question | Pint + uncertainties | ucon | four servers (ucon-mcp, unit-converter-mcp, mcp-units, mcp-gnu-units) |
|---|---|---|---|
| `amb-calorie-joule`: 1 calorie in joules (two exact answers) | incomplete: 4.184, and calls the unit "calorie" | incomplete: 4.184, and calls the unit "calorie" | not judged: the adapters do not report what the server states; two have no unit named "cal" |
| `lab-inch-mm-states-unit`: the answer must carry the unit | pass: "mm" | pass: "mm" | not judged: same gap in the adapters |
| `rel-inch-mm-round-trip`: 7 in to mm and back | pass | pass | pass, all four |
| `rel-square-two-ways`: uncertainty of `s * s` and of `s ** 2` must agree | pass | **fail: 0.0283 against 0.04** | not offered: no tool for propagation |

GTC and measurement-uncertainty-mcp were not run: neither converts units, and they were not installed in this Python.

What the trial shows:

1. **The relation finds, with no reference value, the defect already reported to ucon** (issue 396 there): the two ways of writing a square give different uncertainties. That is what a relation is for.
2. **"Incomplete" on the calorie question is a statement about the question as much as about the tools.** Both libraries take "cal" to be the thermochemical calorie, which is a common and documented choice, and both name the unit "calorie". Whether that should count as not saying which calorie was meant is one of the open questions in `FORMAT.md`. Until it is settled, this verdict must not be reported to anyone as a finding.
3. **"Not judged" is kept apart from the tool.** Where an adapter does not yet pass on what a tool states, the runner says so and gives no verdict on the tool.
4. A first version of the ucon adapter reported the unit as `<UnitProduct mm>`, the programmer's view of the object, and the question failed. That was the adapter's mistake: the library's own short name for the unit is "mm". Corrected before publishing; recorded because it shows how easily an adapter can put words in a tool's mouth.
