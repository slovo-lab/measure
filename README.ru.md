## Простыми словами

**Measure — это поверка для калькуляторов, которыми пользуются ИИ-агенты.**

Языковые модели плохо считают с единицами измерения и погрешностями. Поэтому им дают программы-калькуляторы: «переведи мили в километры», «посчитай погрешность произведения». Таких программ много. Со стороны никто не проверяет, правильно ли считают они сами.

Measure делает именно это, и устроен он как обычная поверка прибора:

1. **Эталон.** Набор задач с заранее известными ответами. У каждого ответа указан источник, в основном публикации NIST, и он пересчитан в точных дробях. Сейчас задач 43.
2. **Испытание.** Одни и те же задачи задаются каждому калькулятору.
3. **Протокол.** Публикуется таблица: где ответ совпал с эталоном, где разошёлся и насколько, а чего калькулятор не умеет вовсе.

Сам Measure ничего нового не вычисляет. Он только сверяет чужие ответы с эталоном.

**Что он уже нашёл.** В первый же день — две ошибки в библиотеке ucon: неверную погрешность числа, умноженного само на себя, и обозначение единицы, которое читается двумя разными способами в зависимости от того, во что переводишь. Обе сообщены авторам.

**Для кого это.** Для тех, кто выбирает калькулятор своему агенту; для авторов калькуляторов, которые получают бесплатную независимую проверку; и для самих агентов, которые по таблице могут решить, какому инструменту доверять.

## Что изменилось в первый день

Сначала Measure задумывался как калькулятор для ИИ-агентов, который работает с единицами измерения и погрешностями. Поиск 24 ноября 2026 года показал, что есть инструменты, которые, судя по их описаниям, это уже делают:

| Инструмент | Что о себе заявляет |
|---|---|
| [ucon](https://pypi.org/project/ucon/) | Библиотека единиц с расчётом погрешностей и сервером для ИИ-агентов |
| [measurement-uncertainty-mcp](https://github.com/kyb8801/measurement-uncertainty-mcp) | Анализ неопределённости по GUM для ИИ-агентов |
| [mcp-units](https://github.com/quantumleeps/mcp-units) | Пересчёт единиц для ИИ-агентов на основе Pint |
| mcp-gnu-units | Пересчёт единиц для ИИ-агентов на основе базы GNU units |

Правило 5 манифеста запрещает делать дубли, поэтому от этого плана мы отказались.

## Замысел сейчас

Независимый испытательный стенд для таких инструментов. В метрологии прибору доверяют потому, что его сравнили с эталоном. Measure делал бы то же самое для калькуляторов, на которые полагаются ИИ-агенты:

1. Открытый набор разобранных примеров с известными ответами, у каждого указан источник (например, примеры из GUM).
2. Программа, которая задаёт одни и те же примеры каждому инструменту.
3. Опубликованная таблица результатов: где инструмент совпадает с эталоном, где расходится и насколько.

Он ничего нового не вычисляет. Он проверяет калькуляторы, которые уже существуют.

## Почему решено делать

Второй круг изучения темы 24 ноября 2026 года ответил на открытые вопросы достаточно, чтобы начинать.

- **Метод давно принят в метрологии.** Проверка программ по эталонным наборам данных с эталонными результатами («эталонные пары») — подход европейского проекта TraCIM, который переносит принцип калибровки на программы. Measure заимствует этот метод, а не изобретает свой.
- **К инструментам для ИИ-агентов его, похоже, никто не применяет.** TraCIM сертифицирует отдельные вычислительные алгоритмы как услугу. Открытой сквозной проверки калькуляторов единиц и погрешностей, к которым обращаются агенты, мы не нашли. Это по-прежнему «не нашли», а не «не существует».
- **С эталонными примерами нужна аккуратность.** Документы GUM защищены авторским правом JCGM, и воспроизводить их можно только с письменного разрешения. Поэтому Measure не копирует их текст. Он начинает с задач с точными ответами (определения СИ, формулы с аналитическим решением) и с публикаций NIST, а на примеры GUM ссылается по номерам.

## Как запустить

```
python3 -m unittest discover -s tests        # проверка пар и программы прогона
pip install -r requirements-adapters.txt     # проверяемые инструменты
python3 -m bench pint                        # задать все пары связке Pint + uncertainties
python3 -m bench ucon                        # то же для ucon
python3 -m bench ucon-mcp                    # сервер ucon для ИИ-агентов
python3 -m bench unit-converter-mcp          # ещё один сервер для ИИ-агентов
python3 tools/make_results.py                # прогоняет оба и переписывает RESULTS.md
```

Каждой паре программа прогона ставит один из четырёх вердиктов: `pass` (сошлось), `fail` (не сошлось), `unsupported` (у инструмента нет функции для такой задачи; это не ошибка) или `error` (сбой). Адаптер только передаёт вопрос инструменту и сам ничего не вычисляет.

## Для кого

- Для людей, которые выбирают инструмент расчёта единиц или погрешностей для ИИ-агента.
- Для авторов этих инструментов: они получают бесплатную независимую проверку и воспроизводимые сообщения об ошибках.
- Для ИИ-агентов: по таблице результатов можно решить, к какому инструменту обращаться.

## Открытые вопросы до начала кода

## Как мы поймём, что не получилось

Действует срок по умолчанию из манифеста: если через восемь недель после первого выпуска результатами не пользуется никто за пределами лаборатории (ни один автор инструмента не ответил, нет внешних issue, нет ссылок), проект уходит в архив с письменным разбором.
